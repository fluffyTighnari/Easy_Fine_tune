# 第 4 步：规范化

**产出**：`work/data/messages.jsonl`、`work/reports/4-normalize.md`

## 跑

```powershell
cd learn
..\.venv\Scripts\python.exe pipeline\normalize.py
```

## 做了三件事

| 做什么 | 规则 |
|---|---|
| 时间重排 | 按时间升序；无时间戳的排最后，保持原相对顺序；重新编号 `mid` |
| 系统消息 | 说话人是「系统」或内容命中（通话时长 / 已取消 / 撤回 / 拍了拍）→ `role: system` |
| 引用块剥离 | `"引用"\n------\n正文` → 只留正文，引用存进 `quote` 字段 |

## 引用块的四种处置

| 状态 | 动作 | flag |
|---|---|---|
| 剥离成功 | 正文入 `text`，引用入 `quote` | `quote_stripped` |
| 后段无正文 | 原样保留 | `quote_no_reply` |
| 前段不是引用 | 原样保留 | `quote_no_quote` |
| 多个分隔符 | 原样保留 | `quote_multiple` |

后三种在第 7 步组样本时排除，不参与训练。

## 报告看什么

| 项 | 要判断的 |
|---|---|
| 时间升序 | 必须是「是」 |
| 系统消息条数 | 通话/撤回/拍一拍各自多少 |
| 剥离成功条数 | 占含分隔符总数的比例 |
| 结构不完整条数 | 越少越好；会打 flag 排除 |
| 剥离样例 | 抽 3 条肉眼确认没剥错 |

## 闸门

| 闸门 | 标准 |
|---|---|
| 时间全部升序 | 是 |
| 引用块处置可解释 | 剥离 + 结构不完整 = 含分隔符总数 |
| 系统消息已归位 | ≥ 1 条（没有系统消息也算通过，报告会显示 0） |

`no_quote` 不为 0 且量很大 → 说明有人的消息正文里本来就带 `------`，看样例确认后再决定是否关掉这条规则。

## 出问题怎么办

| 现象 | 处理 |
|---|---|
| 时间升序 = 否 | 回第 1 步看时间格式，`[YYYY-MM-DD HH:MM:SS]` 以外的格式会解析失败 |
| 剥离样例里正文被截掉了 | 你的引用格式和微信不同，改用方法：把该条的原文发我，加一条正则 |
| 多个分隔符很多 | 说明有人在消息里嵌套引用，这些会被排除，不影响训练 |
